# JBike6 control-theory audit notes

This audit follows the original 2015 MATLAB implementation as the mathematical source of truth. The executable companion in `control-theory.js` implements the state-space and transfer-function equations with tests runnable in Node.

## MATLAB equations and conventions

`JBmck.m` defines `q = [lean angle, steer angle]`, lean right positive and steer left positive, and gives

```text
M0 q̈ + v C1 q̇ + (K0 + v² K2) q = T.
```

Crucially, the MATLAB `JBmck.m` forms `K0` with gravity included in each term. The control implementation must use `K0 + v²K2` directly; multiplying `K0` by gravity again is incorrect. `control-theory.js` expects this MATLAB convention (gravity-scaled `K0`), and rejects singular mass matrices rather than silently proceeding.

The state order from `JBike6Control.m` is interleaved, `x = [q1, q̇1, q2, q̇2]ᵀ`. With `S = M0⁻¹(v C1)` and `K = M0⁻¹(K0 + v²K2)`,

```text
A = [ 0       1       0       0
     -K11    -S11    -K12    -S12
      0       0       0       1
     -K21    -S21    -K22    -S22 ].
```

`C = [1,0,0,0]` observes roll and `D = 0`.

## MATLAB input-channel finding

There is an important inconsistency between the MATLAB example's prose and its actual input matrix. `JBike6Control.m` creates a 4-column `B`, then calls `ss2tf(A,B,C,D,2)`. With its documented coordinate order, the selected second column is `[0; (M0⁻¹)11; 0; (M0⁻¹)21]ᵀ`: generalized torque on `q1` (lean). The steer-torque channel is the fourth column `[0; (M0⁻¹)12; 0; (M0⁻¹)22]ᵀ`. Thus the MATLAB example's selected input is not the physical steer torque despite its prose describing steer torque. The exported `computeStateSpace` preserves the literal MATLAB B matrix and separately returns both `matlabInput` and `steerTorqueInput`; these must not be mislabeled as the same channel.

For the selected input's generalized-force vector `b = M0⁻¹[:,1]`, define

```text
P(s) = [s² + S11 s + K11,  S12 s + K12
        S21 s + K21,        s² + S22 s + K22].
```

Then `denG(s) = det(P(s))`, and the roll numerator is `P22*b1 - P12*b2`. For steer output it is `-P21*b1 + P11*b2`. These expressions are generated by `control-theory.js`; the exact MATLAB input column is used, not the physical steer torque column.

## Schwinn Crown baseline

The original MATLAB fixture is `original Matlab files/JBini_files/JBini_Schwinn_Crown.m` (wheelbase 1.016 m, head angle 1.23879599 rad, trail 0.090968 m, gravity 9.80665 m/s², rider mass 80 kg). The browser preset previously labelled “JBike6 Schwinn Crown (Original Default)” is not an exact parameter port: it uses a 1.076 m wheelbase and different component parameters. Do not claim its outputs reproduce the original MATLAB Schwinn Crown results. Exact comparison requires translating all MATLAB bodies, inertias, orientation angles, and fork/basket coordinates—not adjusting only one parameter.

## Verification

Run numeric regression checks with:

```sh
node --test tests/control-theory-audit.test.js
```

These tests evaluate numeric matrices, MATLAB and steer torque input columns, transfer-function values against direct solution of the second-order equations, and singular-input handling. They do not execute the browser interface or compare the full body-assembly calculation against MATLAB/Control System Toolbox. A browser integration and exact full-parameter Schwinn port remain separate work; until those are completed, the existing page should not be represented as using this companion solver.
